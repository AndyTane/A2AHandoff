# 交接文案配置

入口：主窗口底部「交接文案」。配置位于 `runtime/message-templates.json`。

## 发给 DSH

只发送「执行指令」与可选「补充说明」。文件名或路径直接在执行指令中填写，例如：`读取 docs/NEXT_TASK.md 并执行。`
Claude 的完整回复仅作为本机调度和去重证据，不插入发送内容。两段均为空时不发送。

## 发给 Claude

发送「回复前文 + DSH 完整原文 + 回复后文」。默认以前文末尾的 `[` 和后文开头的 `]` 包裹正文；可自行改成 `<` 与 `>`。
DSH 原始正文不被改写；原文中的中文标点、代码和占位符保持原样。
不自动添加产品名、preview、交接编号、轮次或自动发送说明。内部投递 ID、绑定和回执只保存在本机。

## 保存与核验

保存只更新文案配置，不发送消息，不修改自动开关或绑定，不重发旧回复。恢复默认后仍需保存。已粘贴的旧草稿不会被覆盖。
GUI 预览与 runtime 使用同一纯拼接函数。DSH 方向的预览不含 Claude 正文示例。
去重仍依据原始来源回复；不同来源回复可触发相同读文件指令，修改文案不会绕过去重。
无可见交接编号时，Claude 回执使用准确会话、相邻消息索引和完整正文规范化哈希核验。证据不足保持不确定，不自动重试。
